# Teensy Firmware

## What it is for

Each platform's Teensy drives the eight thruster valves and the air-bearing (puck) valve. The Jetson sends it a command packet over USB serial: `0xAA` then nine little-endian `float`s (eight duty cycles in percent, then the puck on/off). The Teensy turns the duty cycles into **5 Hz software PWM** on the valve pins and switches everything off if no packet arrives for 2 s.

## Function by function

**Lines 8–12.** The pins: thrusters on 0–7, the puck on 8, the status LED on 13.

**Lines 17–21.** The PWM: `PWM_FREQUENCY` = 5 Hz (this must equal the console's Thruster PWM setting, `pwmFrequency`; the diagram's duty cycles assume a 200 ms valve period), generated by a 10 kHz interrupt (100 µs ticks), so a period is 2000 ticks and the duty resolution is 0.05 %.

**Lines 26–35.** The protocol constants (sync byte, nine floats = 36 bytes) and the 2000 ms watchdog.

**Lines 40–56.** State: the current duty cycles (written by the main loop, read by the interrupt), the tick counter, the puck state, the receive buffer and its state machine, the time of the last packet, whether Simulink is "active", and the interval timer.

**Lines 61–88.** `pwmISR`, every 100 µs: advance the tick within the period; for each thruster, on if `tick < duty% × 2000` (always off at 0, always on at 100), written with `digitalWriteFast`.

**Lines 93–102.** `setThrusterDuty`: clamp NaN and negatives to 0, above 100 to 100; a 32-bit store is atomic on the Cortex-M, so no interrupt locking is needed.

**Lines 107–113.** `setPuck`: the air-bearing pin high or low.

**Lines 118–135.** `processPacket`: copy the 36 bytes into nine floats, refresh the watchdog and mark Simulink active, set the eight duty cycles, and the puck on if its value is ≥ 0.5.

**Lines 140–165.** `setup`: drive every valve pin low *before* the interrupt starts, zero the duty cycles, puck off, LED off, start the 100 µs timer at mid priority (so the serial interrupt can pre-empt it), open the serial port at 115200 (the speed is nominal on USB).

**Lines 170–226.** `loop`: read every available byte through the two-state parser (wait for `0xAA`, then collect 36 bytes and process them); if active and the last packet is older than 2 s, set every duty cycle to 0, puck off, and go inactive; the LED shows active/inactive.

## Flashing

Open the `.ino` in the Arduino IDE with Teensyduino, select the board, upload. Then run [[setup_teensy_serial.sh|Hardware-Serial-Setup]] once per platform so the port is usable without root.
