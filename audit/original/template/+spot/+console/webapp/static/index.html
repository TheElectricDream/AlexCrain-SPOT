          Unlock the Data Rate?
          
        
      
          
      
          
        
          The data rate is how often the PhaseSpace cameras send each platform's position during an experiment:
          the lab console streams at this rate when the Experiment tab starts the cameras. The Simulation tab's Data Rate
          and the Experiment tab's are the same setting (dataRate).
          
        
          It is locked because the program is built around it:
          
        
            
          
          • The default controllers' LQR gains are designed for measurements at this rate (MATLAB's
            dataRate is its period), so another rate gives other gains.
            • 
          
          • The measured positions, and the speeds worked out from them, come at this rate, in simulations as in experiments.
            • 
          
          • The program on the platforms keeps the rate it was built with: after a change, build again, and start the
            cameras at the new rate before you run it.
            • 
        
          
        
          Keep the rate the experiment was designed for (10 Hz by default); it is a whole number of Hz, 1 to 960.
          The lock comes back when the page is reloaded.
          
      
          
      
          
        
          
          
          
        
          
      
          
    
          
            

  
    
          
      
          
        
          Unlock the Thruster PWM?
          
        
      
          
      
          
        
          The thruster PWM frequency is how often each thruster valve opens and closes: a duty cycle of 40 %
          at 5 Hz opens the valve for 80 ms every 200 ms (PWMFreq in the diagram).
          
        
          It is locked because it has to match the hardware:
          
        
            
          
          • The Teensy on each platform runs its PWM at a fixed 5 Hz (PWM_FREQUENCY in
            teensy_pwm_control.ino). Another value here makes the diagram's duty cycles wrong on
            the real platforms unless every Teensy is flashed with the same value.
            • 
          
          • The diagram drops valve openings shorter than 7 ms (the valve's opening time), so a higher frequency loses
            the small thrusts, and holds each duty cycle for one PWM period.
            • 
          
          • The program on the platforms keeps the value it was built with: after a change, build again.
            • 
        
          
        
          Keep 5 Hz unless the firmware was changed too. The lock comes back when the page is reloaded.

              Before the Thruster Calibration
              
        
      
              
      
              
        
              The thrust is worked out from how each burn moves the platform, so it is only as good as what the
          console takes the platform's mass, inertia and centre of gravity to be:
              
        
              
          
          
          
          
        
              
        
                
          
              • These are SPOT's default mass properties (from the default scale readings and bifilar test), as the lab
            console's controller uses them. Change them here if the platform carries something else today.
                • 
          
              • A mass 5 % off gives thrusts 5 % off. The torque each burn gives checks the centre of gravity and the
            inertia: a torque ratio far from 1 says they are off.
                • 
          
              • 
          
              • Before each burn the console flies it to the table's centre and sets it down (pucks off) for 5 s; the
            pucks then come on with the thruster firing at full thrust for the burn time. Clear the table around the centre.
                •

              Before the Arm Calibration
              
        
      
              
      
              
        
              The calibration moves the Chaser's arm, one joint at a time, with the real servos:
              
        
                
          
              • The Chaser must rest on the table (not float): the arm's motion would push it. The console keeps
            it resting while the calibration runs.
                • 
          
              • Each tested joint moves up to 25° either way from where it is now. Clear the space around the arm,
            and start with the joints away from their limits.
                • 
          
              • Keep the arm's power switch at hand. Stop (or Esc) on this tab switches the servos' torque off at once;
            so does switching the Chaser off on the Hardware tab.
